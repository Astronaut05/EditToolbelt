# 2026-11-12 · The review's second batch: what a tool page does when things change under a run

**Decision:** the rest of the tool-page findings from the 2026-11-12 review are fixed as below. Each is a call the spec didn't settle.

- **The search sheet loads the first time search is asked for.** Every page carried the search dialog, its results list, the search and the index loader in its first load, about 3 KB. `SearchOverlay` now holds only the key listeners and the header button; `SearchDialog` is a file of its own, fetched on first use and warmed up when the button is pointed at or focused and when Ctrl or ⌘ goes down, so the shortcut finds it loaded. A fetch that fails is tried again at the next ask. The room this made in the 180,000-byte script budget is what the fixes below, and the error page, are paid from: the heaviest tool pages sit about 2,000 bytes under it after this batch, 340 before.
- **A session ends on a new file, on Cancel and on leaving the page.** The run is aborted (which cancels a server job and returns its credits), a redo waiting on its timer doesn't start, and whatever is still reading the old file finds the session changed and sets nothing. An aborted run no longer clears the page itself: whatever aborted it has already set what shows.
- **A run takes the settings as they are when it starts**, not as they were in the render it was created in: a new image no longer runs with the last image's brush strokes, and a setting changed while a file is being read counts for the first silence search.
- **A setting changed during a run makes it run once more** on tools that redo on a change (`autoRun`, `rerun`). Before, the change was dropped and the result and download carried the older settings.
- **A batch made, or being made, with older settings starts over** when a setting changes: its outputs go and its rows go back to queued; a tool that runs on arrival runs again, the others show Start. Not where settings only shape the list (File Checksum's `batchList`: every file is hashed once, whatever the list format), and not in a folder being renamed in place.
- **A file dropped beside the drop zone does nothing.** The browser would open it in place of the page and the work would be gone.
- **Single-run progress is drawn at most every 120 ms**, plus every new stage and the end, as batches already were. Each report drawn is a render of the whole shell.
- **An `image` option keeps its file**, as `file` options do, and Remove Background's view hands the engine the file. The page's CSP lets nothing fetch an object URL, so "Background: Image" could not work.
- **One error page, `app/error.tsx`, in plain markup.** A part of a page that can't be fetched any more (an open tab after a deploy, a dropped connection) used to end in Next's bare "Application error". It now says what happened and offers Reload, which gets the current version. It imports nothing: with the shared `Button` and `MonoLabel` it cost every page 4.7 KB, plain it costs 1.2 KB. There is no `global-error.tsx`: it cost every page another 1.1 KB for errors in the root layout, which renders nothing that loads late.
- **Levels are read on the track's own timeline** (Remove Silence, Split Audio, Subtitle Generator): a track that starts late or has a gap reads as silence there, as the loudness scan already did. Decoded blocks laid end to end put every silence, cut and split point that much early.
- **Whoever opens an audio stream closes it** (`Frames.close`, called in `finally` by Merge Audio, Merge Videos and Replace Audio), so a decoder stops when the run ends, is cancelled or fails, not when the garbage collector finds it.

**Left open:** on a phone, the BPM & Key Finder's tap pad and metronome are drawn under the settings before a file arrives and under the result after, so a file arriving restarts them. Keeping them in one place in the tree means moving the settings column under the workspace on phones, which also moved the result's numbers below the verdict. It needs a layout decision, not a bug fix.

**Why:** these all come from one gap: the shell assumed nothing changes between a run's start and its end. Leaving the page left a paid server job running; a new file, a cancel or a changed setting let the older work land on top of the newer state.

**Reverse:** each is a small, separate change in `packages/ui/src/tool/ToolShell.tsx` (the session counter, the `latest` settings, the `edits` counter, the batch reset in `changeOption`, the window drop guard, `drawGate`). The search split is undone by importing `SearchDialog` statically in `SearchOverlay.tsx`; the error page by deleting `apps/web/src/app/error.tsx`.
