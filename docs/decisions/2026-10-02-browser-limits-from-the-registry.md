# 2026-10-02 · Browser limits come from the registry

**Decision:** the browser limit a tool page checks and states is the registry's `limits.client.maxBytes`. `shellTool()` passes it as `ShellTool.maxBytes`, and the ToolShell uses it for the drop zone, the "browser limit" messages, the joined files' check and Batch Rename's ZIP. The formats line can be a function that is given the limit as the copy states it ("1 GB", `formatLimit`, counted in 1024s like the registry). Pages whose tool has a client limit no longer set `maxBytes` or write the size. `ShellPreset.maxBytes` stays for the tools the registry gives none, the server tools, as their drop zone's own. With neither, the browser takes a file of any size (only an admin override without `client` can do that; the engines still check their own). The engines keep their constants (`VIDEO_LIMITS`, `GIF_INPUT_LIMITS`, `PALETTE_LIMITS`, `AUDIO_LIMITS`); `apps/web/src/tools/limits.test.ts` checks they equal the registry, and fails on a page that sets the limit or writes its size.
**Why:** CLAUDE.md rule 3. About 34 pages repeated the registry's number and its size in their copy, and nothing tied them together, so a changed limit would have left the page checking and saying the old one. The visible copy is unchanged: the formats lines of all 90 built pages are the same before and after.
**Reverse:** give each page its `maxBytes` and size phrase back, make `ShellPreset.maxBytes` required and `formats` a string, and drop `ShellTool.maxBytes` and `limits.test.ts`.
