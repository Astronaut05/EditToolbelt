# 2026-10-02 · Dependabot's two torch alerts wait for the first Modal run

**Decision:** torch stays at 2.10.0 in the GPU images (`apps/worker/src/etb_worker/gpu/requirements-upscale.txt` and `requirements-whisper.txt`) until the first Modal run, which moves it to 2.13 or later along with re-checking the images. Dependabot's two low alerts on main are both this torch: PYSEC-2026-139 (the `.pt2` loading handler, local, no fix yet) and PYSEC-2025-194 (`torch.jit.script` memory corruption, local, fixed in 2.13.0). CI's dependency audit already ignores both by id, with these reasons.
**Why:** neither is reachable from a user's file. The GPU functions `torch.load` only our own weights, pinned by SHA-256 and checked when Modal builds the image, with `weights_only=True`; nothing loads a `.pt2` file or calls `torch.jit.script` on input. The images can't be built or run from this environment (no Modal token, no GPU), so bumping torch now would change them untested; the first Modal run tests them anyway.
**Reverse:** bump `torch` in both `.in` files, recompile them with `uv pip compile --generate-hashes`, update `licenses.json` and drop the two ids from the audit's ignore list.
