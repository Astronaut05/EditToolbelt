# 2026-11-12 · Go public: the site answers anyone, Access stays on /admin

**Decision:** Astro asked for the site to go live. The web service is public by default from now on:

- **`SITE_ACCESS`** (web): `public` unless set to `private`. Public, the pages and the API answer anyone, and the service asks for a Cloudflare Access token on `/admin` only, and only while Access is set up (`CF_ACCESS_TEAM_DOMAIN`, `CF_ACCESS_AUD`). The admin's own sign-in and two-factor check stand behind that either way. `private` is how the site ran until today: every path behind Access, 503 in production until Access is set up. It stays for a staging copy or for taking the site private again.
- **What makes it public is one change in Cloudflare:** the Access application's address goes from the whole domain to `<site>/admin`. Its audience tag stays, so Railway's variables stay. Until then the site is as private as before, because Access answers before Railway. `docs/runbooks/go-public.md` has the steps.
- **`/readyz/worker` is open on the public site.** It says two ages in seconds and nothing else, its answer is remembered for 15 s, and Watch then needs no Access token. This replaces the plan to give it an Access rule of its own (`STATUS.md`, Next): a service token expires after a year and CI's had already stopped working unnoticed, which is how Watch failed for weeks. `/readyz` remembers its answer for 10 s (2 s while something is down) for the same reason: it is open, and it costs a query and a billed storage call.
- **The origin lock, `ORIGIN_AUTH_SECRET`:** optional. A Cloudflare Transform Rule adds the secret as the `x-origin-auth` request header and the web service refuses requests without it, except Railway's own health checks. Without it, a request sent straight to Railway's edge with the site's Host skips Cloudflare and can name any client address, which defeats the per-address rate limits and `ADMIN_IP_ALLOWLIST`. The limits that must hold either way count per account, per key or in all.
- **Sign-in links** are limited per caller (10 in 15 minutes), per email address (3 in 15 minutes) and in all (300 an hour), before anything is written or sent. Better Auth's own limiter is off, since it counts by IP address and none is kept. Over HTTP, `/api/auth` answers only where an emailed link and Google's redirect land; everything else the site calls on the server.
- **Rate-limit keys** count an IPv6 address by its /64.
- **The ops checks ask the site which it is** (`/healthz` says `access`, to anyone). A public site must answer strangers and keep `/admin` shut; a private one must show them the Access login. Smoke and Watch no longer skip when the Access token is missing: a check that cannot run fails and says why.
- **The page CSP keeps `'unsafe-inline'` on public pages for now** (`2026-10-02-server-build-csp.md` left this to Go public). Public pages render only our own text, personal pages keep their nonce policy, and hashes per page stay a follow-up.
- **`/contact`** publishes `CONTACT_EMAIL` once it is set; until then it says an address is on its way. The privacy, terms and refunds pages stay marked Draft: their final text is Astro's, before money is taken.

**Why:**
- The docs already said Go public "takes Access off (or narrows it to `/admin`); nothing else about hosting changes". But the service itself refused every request without an Access token, so taking Access off would have shown every visitor 403.
- A default of public needs no change to Railway's setup, which would wait on an approval; the site keeps working behind Access until the one Cloudflare change.
- Three things were safe only because Access stood in front and had to be closed first: unlimited sign-in mail, the open health checks, and trust in `CF-Connecting-IP`.

- **`.railway/railway.ts` is unchanged.** The two optional variables (`CONTACT_EMAIL`, `ORIGIN_AUTH_SECRET`) are set on the `web` service in Railway's dashboard for now: the `RAILWAY_TOKEN` secret turned out to be invalid, so the Railway workflow can't plan or apply, and a change to that file would have left a failing check on `main`.

**Reverse:** set `SITE_ACCESS` to `private` on the `web` service in Railway, and give the Access application the whole domain again. CI's token secrets must then name a live service token.
