# 2026-10-02 · Calculator fields take in early edits

**Decision:** the calculator fields (`NumberField`, `TextField`, `TextAreaField` and `SelectField` in `apps/web/src/tools/calc-ui.tsx`) check on mount whether the element still holds the value React rendered. If the person changed it before React took the field over, the field reports what it holds through `onChange`, as if just edited. A field React rendered itself always holds its value, so nothing happens then. `color-qr.spec.ts` holds the QR tool's script back, picks Wi-Fi, then lets it load.
**Why:** the QR Wi-Fi test failed in WebKit on PR #71's CI (run 36999320855, job 110813129317): no Network name field came for 30 s, a run after it passed. Calculator pages are prerendered and their tool's own chunk can arrive after the load event, so the test picked Wi-Fi on the prerendered select. React 19 can't hydrate the field yet, so it drops the change without replaying it and keeps `url`: the select said Wi-Fi, the form showed the link field, and picking Wi-Fi again changed nothing. A person on a slow network gets the same page. Holding the chunk back fails every time without the fix: in Chromium and phone locally, and 4 of 4 in WebKit (debug run 37010634676), with CI's error and its empty `alert:` line; the heartbeat showed the select at `wifi` while React's props said `url`. With the fix it passed 8 of 8 in WebKit (37010972469), and in Chromium and phone locally.
**Reverse:** remove `useEarlyEdit` from `calc-ui.tsx` and the "a choice made before the tool has loaded still counts" test from `color-qr.spec.ts`.
