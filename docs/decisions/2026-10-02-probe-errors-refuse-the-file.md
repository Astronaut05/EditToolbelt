# 2026-10-02 · An upload the probe can't handle is refused, not retried

**Decision:** when probing an upload fails with an error nothing expected (anything but a refusal, a missing file, a storage outage or a database error), the worker records `probe_error = 'UNSUPPORTED_FORMAT'` on it, so the web asks for another file as it does for a damaged one, and logs `upload.probe_failed` with the error's type only. Database errors still leave the upload for the slot to try again. Both slot loops also catch anything else, log `slot.error` with the type, wait 5 s and carry on.
**Why:** an unexpected error used to roll the probe back and leave the upload unprobed, so it ended the slot thread, and the next slot that picked it up died the same way: one MKV tagged `rotate=abc` stopped every server tool, with no alert. Refusing that one file is the failure that can't spread. The cost: an error from the worker's own machine during a probe (a full disk while downloading) refuses a good file too, and the user uploads it again.
**Reverse:** remove the `except Exception` in `probe_next` (`apps/worker/src/etb_worker/probe.py`); the slot's catch-all then tries the upload again every 5 s instead.
