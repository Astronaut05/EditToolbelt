# 11 — Security

User files are untrusted binary input processed by complex parsers (ffmpeg, image decoders). Treat every file as hostile.

## File intake

- Validate by **content**, not extension or claimed MIME: sniff magic bytes in the browser (for UX) and **probe on the server** (ffprobe / Pillow with strict limits) before any processing. Mismatch → reject with `UNSUPPORTED_FORMAT`.
- Limits enforced server-side from the registry (bytes, duration, pixels) regardless of what the client says.
- **Decompression bombs:** cap decoded pixels (e.g. 100 MP, config) — set Pillow `MAX_IMAGE_PIXELS`, check dimensions from headers before decoding; cap video resolution × duration; cap audio duration.
- Archives: we don't accept ZIP uploads in v1. (Batch uploads are multiple files.)
- SVG is **never accepted as input** in v1. SVG output (QR codes) is generated by us and contains no scripts.
- Original filenames never leave the browser.

## ffmpeg and native tools on the server

- Run in a dedicated worker container: non-root user, read-only root filesystem, per-job temp dir as the only writable path, **no outbound network** (egress blocked except to storage and the GPU backend from the orchestrating process — the ffmpeg subprocess itself gets no network namespace access), seccomp default profile, CPU/memory cgroup limits.
- Always pass arguments as a list; never interpolate into a shell.
- Set `-protocol_whitelist file,pipe` and never let user data choose a URL, demuxer, or filter graph. Playlists (HLS/concat lists) are never read from user input — the concat demuxer only reads lists we generate.
- Fixed allowlist of input demuxers/decoders per tool; reject anything else after probe.
- Wall-clock timeout per tool; kill the process group on timeout.
- Keep ffmpeg and image libraries updated (monthly base image rebuild + on CVE alerts).

## Storage

- Buckets are private. Access only via presigned URLs: upload URLs expire in 15 min and are bound to exact key and size; download URLs expire in 10 min.
- Object keys are random (UUIDv4), not derived from user data.
- Server-side encryption at rest (provider default). TLS everywhere.
- Lifecycle rules (1-day expiration + 1-day incomplete-multipart abort) verified on every deploy by a check in `/admin/system`.

## Auth and accounts

- Better Auth: magic links expire in 15 min, single use; OAuth state/PKCE; session cookies httpOnly + Secure + SameSite=Lax; session rotation on sign-in.
- CSRF protection on cookie-authenticated state-changing routes.
- API keys: 32 bytes random, prefixed (`etb_live_`/`etb_test_`), stored as SHA-256 hash, shown once, scoped, revocable. Constant-time comparison.
- Admin: role check server-side on every admin route/action + TOTP 2FA + audit log. Optional IP allowlist.
- Rate limits: Cloudflare edge rules (per IP) + app-level per user/key (auth endpoints, uploads, jobs, checkout).

## Web app

- Strict Content Security Policy: scripts from self + Paddle (checkout route only); `wasm-unsafe-eval` only on tool routes that need WASM; `frame-ancestors 'none'`. **No nonces on public pages:** in Next.js a nonce forces every page to render per request — no static generation, no ISR, no CDN caching — which breaks the speed budgets in `10`. Public pages stay static and use Next's hash-based CSP (`experimental.sri`); nonces only on routes that are dynamic anyway (`/account`, `/admin`, `/credits/buy`). SRI is experimental in Next.js, so M1 must prove a static tool page loads with zero CSP violations; if it can't, fall back to `script-src 'self' 'unsafe-inline'` on static pages (we render no user HTML) and record that decision.
- COOP/COEP only on routes that need cross-origin isolation (see `01-architecture.md`).
- Security headers: HSTS (preload after launch), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` minimal.
- Output encoding by default (React); no `dangerouslySetInnerHTML` except JSON-LD built from our own registry.
- Zod validation on every API input; reject unknown keys.

## Payments

- Webhook signature verified before anything; raw payload stored; processing idempotent on event id.
- Never trust client-reported payment success — credits are added only from webhooks.

## Secrets and supply chain

- Secrets in environment variables from the host's secret store; never in the repo; `.env.example` lists names only.
- Separate keys per environment. Rotate on any suspicion.
- Lockfiles committed; `pnpm audit` and `pip-audit` in CI; Dependabot/Renovate weekly.
- Every new dependency goes through the license register (`13-licenses.md`), which doubles as a review point.
- Docker images pinned by digest; built in CI; minimal base images.

## Backups and recovery

- Postgres: daily full backup + WAL/PITR (7 days) if the host supports it; weekly restore test to staging (automated script).
- No user files to back up by design.
- Runbook `docs/runbooks/` (created during milestone 4): restore DB, rotate secrets, disable a tool fast, drain workers, handle a webhook outage.

## Incident basics

- Admin can disable any tool instantly (status `disabled` or maintenance message).
- If a personal-data breach is suspected: contain, assess, notify the authority within 72 h where required, notify users if high risk. Keep a template in the runbooks.
